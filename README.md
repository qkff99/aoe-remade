# Anomaly Optimized Engine Remade

**AOE Remade** — форк [X-Ray Monolith](https://github.com/themrdemonized/xray-monolith) для **S.T.A.L.K.E.R. Anomaly 1.5.3**, основанный на его многопоточной версии. Объединяет собственные оптимизации и адаптированные наработки разных движков S.T.A.L.K.E.R.: ускорение рендера, более равномерное время кадра, фоновую загрузку ресурсов и переработанную работу Lua GC.

## Основа и источники

Спасибо авторам исходных реализаций, инструментов и исправлений:

## Отличия от исходного Monolith MT

Ниже перечислены дополнения и изменения AOE Remade поверх исходной версии.

### Время кадра и многопоточность

- Новый ограничитель FPS: точные сроки выдачи кадра, высокоточный таймер ожидания и коррекция после пропущенного срока. Лимит применяется перед Present и сохраняет дробную часть периода кадра.
- Фоновые задачи с ограничением по времени могут использовать оставшийся интервал до выдачи кадра, включая ожидание ограничителя FPS.
- Lua GC может продолжать работу после временной передачи Lua основному потоку для отрисовки интерфейса.
- `mt_scheduler`, `mt_schedulerRT` и `mt_level_call` закреплены в состоянии `1`; старые настройки больше не возвращают эти обновления в основной поток.
- Из IX-Ray адаптированы ограничения и сглаживание временного бюджета шедулера.
- A-Life умеет продолжать обход и обновления в следующих кадрах, сохраняя позицию и квоты работы.
- Обновление HUD-привязок актора согласовано с владельцем основного потока при фоновом выполнении игровой логики.

### Lua и сборщик мусора

- Добавлен режим `lua_gc_always`: сборщик выполняет последовательность небольших шагов в доступном фоновом окне кадра.
- Доступ к Lua согласован между игровой логикой, сборщиком, интерфейсом и Lua-вызовами из движка. Перед передачей владельца выполняются необходимые ожидания.
- Часть подготовки GC, включая повторную маркировку и поиск userdata для финализации, разбита на возобновляемые этапы.
- Переработана подготовка финализаторов userdata перед атомарной фазой GC. Для отбора кандидатов используется компактное представление вместо прежних дополнительных колец ссылок.
- Сохранены обработка слабых ссылок, воскрешения объектов и порядок финализации; предусмотрены переходы к полной сборке, закрытию VM и прежнему режиму GC.
- В безопасных точках учитывается давление на память. Автоматическая сборка при выделении памяти согласована с текущим владельцем Lua.
- Освобождение звуков из Lua-финализаторов передаётся владельцу звуковой подсистемы.

### Параллельная подготовка рендера DX11

- Поддерживаемые проходы теней локальных источников, солнечных каскадов и дождя записываются в отдельные контексты DX11 на рабочих потоках.
- Контексты имеют собственные буферы констант, динамические потоки геометрии и кеши состояний.
- Подготовка и запись команд перекрываются с другой работой кадра. Результаты локальных источников публикуются порциями с сохранением порядка освещения.
- Работы распределяются с учётом стоимости скелетной геометрии; устранены повторные обходы в подготовке локальных теней.
- Для рабочих задач фиксируются завершённые позы моделей и входные данные рендера. Неподдерживаемые материалы и проходы сохраняют обычный путь исполнения.
- Подготовка видов, иерархий и пакетов отрисовки использует копии входных данных и повторно используемые рабочие буферы. Готовность и актуальность результата проверяются перед применением.

### Отсечение и геометрия

- HOM использует консервативную проверку глубины от крупных уровней к мелким; построение уровней глубины и очистка растра ускорены SSE2.
- Расстояния до треугольников HOM рассчитываются перед сортировкой, вместо повторного расчёта при сравнениях.
- Устранены точные дубликаты фрустумов секторов. Проверки объединения фрустумов прекращаются после полного включения объекта.
- Исправлены отбрасывание границ позади камеры, обработка частично видимых LOD-детей и отсечение по экранной площади.
- Соседние видимые диапазоны совместимой статической геометрии объединяются для отрисовки. Невидимые промежутки сохраняются.
- Полностью выбранные совместимые группы статической геометрии объединяются в теневых проходах.
- Удаление объектов из узлов пространственной базы использует сохранённый индекс элемента.

### Солнце и локальные источники света

- Пространственная выборка для солнечных каскадов выполняется общим обходом с отдельными масками плоскостей для каждого каскада.
- Иерархии отбрасывающей тень геометрии проверяются относительно видимых получателей теней до спуска к дочерним элементам.
- Убрана неиспользуемая подготовка границ получателей для дальнего каскада в режиме полного объёмного затенения; исправлены границы пустых объёмов отбрасывающей тень геометрии.
- Восстановлена корректная работа GPU-запросов видимости света при включённом апскейлере.
- Обычные GPU-запросы отсечения включены также для источников без теней.
- Добавлен кеш глубины теней локальных источников. Подходящая неизменившаяся часть теневой карты используется повторно.
- Добавлена проверка влияния локального света на видимые поверхности с учётом глубины, направления, дальности и затенения. Для точечных источников она применяется к отдельным граням.
- Результаты GPU-проверок читаются асинхронно. Пока новый результат не готов, сохраняется последнее подтверждённое решение; новые проверки продолжают выдаваться.
- Видимость привязана к камере, трансформации источника, разрешению рендера и виду. Скрывающие результаты от изменившегося вида отбрасываются, устраняя мерцание отдельных конусов при движении камеры.
- Добавлены экранные метки источников и дамп причин, по которым они продолжают участвовать в рендере.

### Состояния рендера, константы и модели

- Пропускаются повторные записи неизменившихся констант и обращения к неиспользуемым назначениям констант.
- Самплеры передаются в DX11 только в изменившихся диапазонах с учётом сброса состояния и освобождённых слотов.
- Поиск констант подготавливается заранее; уменьшено число повторных разрешений привязок при обновлении буферов.
- Повторно используются совпадающие произведения матриц объекта, вида и проекции, а также матрицы неподвижных деревьев.
- Текущие и предыдущие упакованные палитры костей кешируются по фактическим матрицам. Совместимые массивы костей записываются блоками.
- Постоянная геометрия полноэкранного прямоугольника повторно используется в проходах SMAA.
- Исправлена потеря детального цвета в дальних материалах статической геометрии и принудительный выбор слишком упрощённого материала ландшафта.

### Трава и деревья

- Для установившихся слотов травы кешируются подготовленные CPU-блоки констант с проверкой матриц, прозрачности и состава экземпляров.
- Ближайшие ожидающие слоты травы выбираются за один проход.
- Деревья повторно используют неизменившиеся общие константы. Совместимые части теневой геометрии используют общий буфер индексов и объединённую отрисовку.

### Частицы

- Совместимые спрайты частиц проверяются на попадание во фрустум до построения геометрии четырёхугольников.
- Рабочий поток публикует готовое состояние частиц для рендера: вершины, границы и дочерние элементы. Это уменьшает необходимость ждать обновление непосредственно в проходе отрисовки.
- Согласованы время жизни опубликованных данных, интерполяция и состояния для разных видов рендера.

### Звук и подгрузка текстур

- Обработка звукового backend вынесена в отдельный поток с передачей параметров слушателя и источников через снимки состояния.
- Декодирование OGG, подготовка PCM и подгрузка метаданных звука выполняются в фоне.
- Создание и запуск ещё не подготовленного игрового звука ставятся в очередь; воспроизведение начинается после готовности данных. Позиция, громкость и другие изменения параметров сохраняются до запуска.
- Явный запрос `Length()` сохраняет точную длительность: при необходимости он ждёт метаданные именно запрошенного звука.
- Подгрузка игровых DDS-текстур выполняется в фоне. Рендер использует временное незаполненное представление, пока ресурс не готов, и не ждёт его непосредственно при привязке текстуры.
- Добавлено удержание ссылок на текстуры во время фоновых задач и отложенных операций; завершение загрузок согласовано с уничтожением ресурсов.

### DLSS и FSR

- В DX11 интегрированы **NVIDIA DLSS Super Resolution** и **AMD FSR 3 Super Resolution** из форка brodrigz.
- Поддерживаются DLAA / Native AA, Quality, Balanced, Performance и Ultra Performance; добавлен **Ultra Quality** с разрешением между нативным и Quality.
- Разделены внутреннее разрешение сцены и разрешение вывода. Интерфейс, PDA и постобработка согласованы с масштабированием изображения; добавлены настройка резкости, выбор пресета DLSS и кеширование вариантов самплеров.
- Исправлено взаимодействие апскейлеров с отсечением света и приватными контекстами рендера.

Для апскейлеров нужен соответствующий комплект шейдеров и runtime-библиотек. Совместимость шейдерных модов определяется используемым комплектом.

### Запуск, файловая система и интерфейс

- Ускорены начальное сканирование каталогов VFS и построение файлового каталога: пакетное перечисление файлов, устранение повторных перечислений и упорядоченная регистрация результатов с сохранением приоритетов.
- В парсерах INI / DLTX сокращены копирования строк и временные выделения памяти.
- Проверка повторных XML-ID использует хеш-набор вместо попарного сравнения.
- Поиск игровых материалов по имени, ID и паре материалов использует индексы; подготовка звуковых метаданных материалов выполняется на рабочих потоках.
- Чтение отдельных описаний частиц при запуске распараллелено; создание шейдеров и применение результатов сохраняют исходный порядок. Чтение THM остаётся последовательным.
- Убраны автоматические отчёты памяти, задерживавшие появление первого меню.
- Текстуры карты PDA за пределами видимой области отбрасываются до отрисовки.
- Исправлены многопоточное владение `shared_str`, завершение фоновых загрузок и обработка активации окна после уничтожения ввода.

### Профилирование и диагностика

- Добавлены сборки **ProfiledDX11** с [Optick](https://github.com/bombomby/optick) и **TracyDX11** с [Tracy](https://github.com/wolfpld/tracy).
- Добавлены CPU-захваты игрового процесса, автоматические захваты запуска до первого меню и загрузки сохранения до готового кадра после прогрева.
- Расширены метки файловых операций, INI / DLTX / DXML, ресурсов, рендера, звука, частиц, Lua GC, шедулера и A-Life.
- Для Tracy добавлен Lua-мост `PROF_EVENT_BEGIN`, `PROF_EVENT_END` и `PROF_EVENT_CLOSURE`.
- В поставляемом исходном коде Optick исправлены размер ETW-буфера и построение дерева событий при увеличении больших захватов. Добавлена [утилита расстановки меток](util/prof_event_marker_gui.py).
- При Lua OOM сохраняются размер неудачного выделения, состояние GC, заполнение низкоадресного пула и состояние системной памяти.
- При ошибке `CreateInputLayout` сохраняются декларация вершин, сигнатура шейдера и контекст ошибки для последующего разбора.
- Обработчик необработанных исключений сохраняет исходный контекст падения и минидамп до дальнейшей диагностики.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `r__framelimit <0–500>` | Лимит FPS; `0` снимает пользовательский лимит в игре. |
| `lua_gc_always 1` | Фоновая пошаговая работа GC; включена по умолчанию. `0` возвращает прежний режим GC. |
| `r4_mt_local_shadows 1` | Параллельная запись поддерживаемых локальных теней и освещения DX11. |
| `r4_mt_sun_shadows 1` | Параллельная запись солнечных теней DX11. |
| `r4_mt_rain_shadows 1` | Параллельная запись дождевых теней DX11. |
| `r4_static_light_cache 0/1/2` | `0` — выключить новый кеш; `1` — кеш глубины теней; `2` — кеш и отсечение по видимым получателям света. По умолчанию `2`. |
| `r4_light_debug 1` | Показать метки локальных источников, включая находящиеся за препятствиями. |
| `r4_light_debug_dump` | Записать причины видимости и результаты проверок источников в лог. Для истории запросов предварительно включить `r4_light_debug 1`. |
| `optick_do <1–10000>` | Записать указанное число кадров в сборке Optick. |

Для автоматического захвата используются аргументы EXE `-optickstartup` и `-optickloadgame`. Снимки сохраняются в каталог логов. Эти аргументы необходимо передавать при запуске процесса.

## Сборка из исходников

Нужны Windows x64, MSBuild / Visual Studio с инструментами **v143**, Windows SDK и компонентами **MFC / ATL**. Решение проекта — `src/engine-vs2022.sln`.

В Developer PowerShell:

```powershell
git clone --branch AOE-Remade https://github.com/qkff99/aoe-remade.git
cd aoe-remade
git submodule update --init --recursive
cd src
msbuild engine-vs2022.sln /p:Configuration=ProfiledDX11 /p:Platform=x64
```

`DX11` — обычная сборка, `ProfiledDX11` — сборка с Optick, `TracyDX11` — с Tracy. Результат сборки Optick: `_build/_game/bin_dbg/AnomalyDX11Optick.exe` и соответствующий PDB. Для разбора вылетов PDB должен соответствовать используемому EXE.
